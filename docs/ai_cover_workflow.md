# ИИ-генерация обложек по референсам: воркфлоу для Дарьи

## Почему этого нет в отчёте

В рамках исследования обложки собраны **только из реальных кадров** (стоп-кадры её
опубликованных reels + чистые слайды каруселей). Генерация фотореалистичного
изображения лица реального человека — даже одного кадра, даже «для превью» — не
выполнялась принципиально: подрядчик (в данном случае ИИ-агент) не может
верифицировать согласие человека на синтез его внешности, а изображение «Дарья
говорит в камеру», которого не существовало, — это по определению синтетическая
внешность реального человека.

Если Дарья сама хочет генерировать обложки по своим референсам — это её внешность
и её решение. Ниже готовый воркфлоу, запускаемый от её имени, с её ключом.

## Честная рекомендация: сначала попробуйте без генерации

Для обложек reels генерация почти всегда **не нужна**:

1. Обложка reels должна совпадать с содержимым — стоп-кадр из самого видео
   всегда совпадает по определению. Все 13 разобранных виральных reels ниши
   открываются реальной говорящей головой.
2. `scripts/generate_feed_previews.py` собирает обложку из любого стоп-кадра
   одной командой (кроп вшитых субтитров поддерживается).
3. Синтетические лица до сих пор дают артефакты (кожа, зубы, кромка волос) —
   для бренда о доверии и «настоящести» это прямой риск.

Генерация оправдана для **фоновых сцен без лица** (интерьер, природа, натюрморт
для каруселей) — там рисков нет вообще.

## Воркфлоу (Gemini API, модель с генерацией изображений)

Модель: `gemini-2.5-flash-image` (генерация/редактирование изображений,
принимает референсные фото). Ключ — свой, в `GEMINI_API_KEY`.

```bash
curl -s "https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-flash-image:generateContent?key=$GEMINI_API_KEY" \
  -H 'Content-Type: application/json' \
  -d @request.json
```

`request.json` — референсы + промпт (изображения передаются как inline_data
base64 или через Files API, см. scripts/gemini_video.py для upload-хелпера):

```json
{
  "contents": [{
    "parts": [
      {"inline_data": {"mime_type": "image/jpeg", "data": "<base64 кадра-референса 1>"}},
      {"inline_data": {"mime_type": "image/jpeg", "data": "<base64 кадра-референса 2>"}},
      {"text": "<промпт из списка ниже>"}
    ]
  }],
  "generationConfig": {"responseModalities": ["IMAGE"]}
}
```

Референсы: 3–5 её кадров «говорю в камеру» из data/target/own_videos/
(кадры извлекаются: `ffmpeg -ss 9 -i video.mp4 -frames:v 1 frame.jpg`).

## Промпты под её дизайн-систему

Общая рамка (добавлять к каждому): *«Вертикальный кадр 4:5, тёплый мягкий свет,
эстетика спокойного велнес-бренда, натуральная кожа без ретуши-пластика,
композиция: лицо в верхней трети, нижняя треть свободна под текст»*.

1. **Кресло/эксперт**: «Та же женщина с референсных фото говорит в камеру, сидя
   в кресле у окна, кремовый кардиган, расфокусированный светлый интерьер»
2. **Провокация**: «Та же женщина, чёрный топ, смотрит прямо в камеру, серьёзное
   спокойное выражение, тёмный фон, драматичный мягкий свет сбоку»
3. **Телесность**: «Та же женщина, рука у груди, глаза прикрыты, профиль/три
   четверти, очень мягкий утренний свет»

Типографика накладывается ПОСЛЕ генерации тем же шаблоном
(`scripts/generate_feed_previews.py`): кикер с разрядкой → линия → заголовок
Playfair Display 500 кремовый #f4edda → курсивный подзаголовок.

## Проверка результата перед публикацией

- Руки/зубы/серьги симметричны? (типичные места артефактов)
- Родинки/черты совпадают с реальными? (аудитория заметит подмену)
- Кадр не «пластиковый» рядом с настоящими? — положить рядом с реальным кадром
  из ленты и сравнить на телефоне, не на мониторе.
